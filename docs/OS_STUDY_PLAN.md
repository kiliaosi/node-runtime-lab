更新日期：2026-10-30。

## 目标与范围

用户明确要求操作系统按深入掌握来学。以 Linux 的系统编程、核心机制、性能诊断与内核实现为主线；在家庭原生 Windows 环境做进程、内存、同步与完成式 I/O 的机制对照。保留后续 libuv、V8、Node.js 方向，用运行时的真实问题检验操作系统知识。

“精通”作为长期能力目标，用可复现产物和独立分析能力评估。进度分别记录机制理解、用户态实现、故障诊断、内核实现四个层次。

## 学习顺序与产物

下表是课程规划，各项当前均未验收。每个单元分若干小课，先解释新概念和语法，再让学生动手实现。

| 单元 | 核心问题与深入范围 | 主要实验或产物 |
| --- | --- | --- |
| OS00 执行与硬件基础 | 指令、寄存器、调用约定、特权级；启动与装载；系统调用、异常、中断；缓存、MMU、TLB、设备与 DMA 的分工 | 从用户代码追到一次内核入口和返回；区分库函数调用、内核态切换与线程切换 |
| OS01 进程与资源 | fork/exec/wait、地址空间、凭据、fd 与打开文件对象；信号、继承、退出与回收；ELF 与动态链接衔接 | 逐步写出支持执行、重定向、管道和子进程回收的 mini-shell；分析资源继承和失败清理 |
| OS02 线程、调度与时间 | 线程与进程共享边界、运行状态、切换、抢占、公平性、延迟、亲和性、多核/NUMA；单调时钟与定时器 | 对照 CPU 工作、阻塞等待与锁等待，记录调用栈及调度证据；说明吞吐、响应时间与公平性的取舍 |
| OS03 虚拟内存 | 页表、地址翻译、缺页、COW、mmap、分配器；虚拟空间与驻留内存；回收、换页、内存压力与 OOM | 分配/触页/COW 实验和一个小型分配器；解释地址空间、驻留页及缺页计数的变化 |
| OS04 并发与同步 | 原子性、可见性、顺序；硬件与 C/C++ 内存模型；锁、条件变量、信号量、futex；竞争、死锁、饥饿与优先级反转 | 实现有界生产者消费者队列与线程池；复现竞争或丢失唤醒，修复并验证；认识 volatile 的适用边界 |
| OS05 文件系统与持久化 | VFS、inode、目录项、打开文件对象；页缓存、写回、fsync、日志和崩溃一致性；存储设备与文件系统接口 | 文件共享偏移实验；实现可恢复的追加日志；区分写入成功、进程崩溃恢复和断电持久性证据 |
| OS06 I/O 与事件机制 | 短读写、EINTR/EAGAIN、缓冲；阻塞/非阻塞与同步/异步；readiness/completion；epoll、eventfd、pipe、io_uring 与 IOCP | 逐步实现 epoll echo server，处理部分读写、背压与优雅退出；在 Windows 写对应完成式 I/O 实验并比较资源生命周期 |
| OS07 网络路径 | socket 生命周期、TCP 状态与收发队列、流量/拥塞控制、协议栈与网卡路径；唤醒、超时和背压 | 用本地客户端制造慢读、断连和连接压力；结合抓包、系统调用及队列指标解释行为 |
| OS08 隔离、权限与限额 | 身份、权限、capabilities、namespace、cgroup、资源限制；容器与虚拟机边界；权限模型贯穿前面各单元 | 在独立实验环境中比较 CPU/内存限制、命名空间隔离和权限失败，解释应用看到的错误与资源统计 |
| OS09 内核实现与综合诊断 | 在教学内核中实现机制，再追踪固定版本 Linux 实现；性能取证、回归测试与设计取舍 | xv6 的系统调用、页表/COW或同步实验；在独立 VM 修改一个小型 Linux 内核路径；独立诊断一个未预告原因的故障并验证修复 |

队列、树、堆、位运算、必要汇编和基础测量方法随对应机制补齐。每次给出一个可完成的实验，不同时抛出整张任务表。

## 每个单元的学习闭环

1. 画出对象、状态、资源归属和关键路径，先预测实验结果。
2. 学习机制、API 契约与设计取舍，区分通用原理和特定实现。
3. 学生手写正常路径和一个可控失败案例，处理错误和清理。
4. 使用日志、调试器、系统调用、调度/内存/性能观测收集证据；工具按当前环境能力选用。
5. 在固定版本源码中追一条路径，指出关键数据结构、锁、等待队列及唤醒点。
6. 改变一个条件，验证模型；性能结论记录负载、重复测量、噪声和适用范围。
7. 学生独立完成一个相近变体，解释机制、故障及修复，再更新笔记和进度。

编译命令与实际控制台输出对学生可见；助手负责检查和反馈，学生承担核心实验实现。自动化验证覆盖实际风险与边界，不用测试数量替代理解。

## 验收与后续课程衔接

- 核心机制验收：能独立完成进程/管道、并发队列、虚拟内存观测、文件持久化、事件 I/O 实验，解释失败路径和资源生命周期。
- 内核实现验收：在教学内核和选定 Linux 子系统完成可解释的修改，能指出不变量、同步要求和回归证据。
- 综合诊断验收：面对未预告原因的高 CPU、锁等待、内存增长、I/O 延迟或资源耗尽问题，提出假设、选取证据、定位原因并验证改动。
- 迁移验收：将同一个机制用于 libuv/Node 的真实调用链，并明确 Linux 与 Windows 的实现差异。

核心机制通过后可以用 libuv 的真实问题继续深化 OS，内核实现和诊断项目持续推进。F03 的完整验收仍需覆盖上述各层；原 F-GATE 单独记录语言、构建、调试与基础运行库阅读能力。

## 材料与版本规则

- 理论主线：[Operating Systems: Three Easy Pieces](https://pages.cs.wisc.edu/~remzi/OSTEP/)，使用作者提供的章节、习题和项目。
- 用户态接口：[Linux man-pages](https://www.kernel.org/doc/man-pages/)，核对参数、返回值、错误与版本差异。
- 简化实现：[MIT xv6-riscv](https://github.com/mit-pdos/xv6-riscv)，按教学内核理解机制，并与 Linux 实现比较。
- 真实内核：[Linux Kernel Documentation](https://docs.kernel.org/)，结合固定源码与实际系统配置阅读。
- Windows 对照：[Microsoft IOCP 文档](https://learn.microsoft.com/en-us/windows/win32/fileio/i-o-completion-ports)，进程、内存与同步主题按需补相应官方资料。

进入内核实验前记录运行中的内核发行版、完整版本、架构、配置和相关补丁。Rocky 的发行版实现与另选的上游实验内核分别记录；文档页与源码行为逐项对应。xv6 固定 commit 并补齐必要 RISC-V 知识，保留与当前 x86-64 环境的架构区别。

内核修改、资源耗尽和崩溃恢复实验在可重置的 VM 或教学模拟器中进行；原生 Windows 的观测与 IOCP 实验仍在 Windows 完成。WSL 如用于工具，不计作 Windows 内核行为的验证。本轮只更新课程，没有安装依赖或启动内核实验。
