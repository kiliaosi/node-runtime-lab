# F03：文件描述符、进程与调度

整理日期：2026-11-23。文件描述符实验沿用此前实测，进程、信号、死锁与调度部分记录课堂分析和习题。

## 文件描述符实验

- fd 是进程自己的描述符表索引。复制整数不创建新描述符。关闭后，编号可能被下一次 open 复用，旧整数此时可能指向另一个文件。
- 两次独立 open 即使打开同一个文件，偏移也各自维护。dup 返回新 fd，与原 fd 引用同一个打开文件对象，共享偏移。关掉其中一个 fd，另一个仍可使用。
- fd_reuse 的正常路径及两次 open 分别失败的路径均已验证。fd_offset 严格构建并验证两组正常结果：dup 共享偏移得到 ABCX，独立 open 得到 XBC。详见 [OS00 实验入口](../labs/00-foundations/os-runtime/00-syscalls/README.md)。
- O_APPEND、lseek、dup2 重定向和保存原输出已做概念推演。dup2 独立练习尚未实现。

## 进程与信号

- 内核保存进程管理信息和运行上下文。进入内核态与线程切换是两个动作。就绪、运行、阻塞和挂起按教材模型理解，不能直接套用到 Linux 的进程状态字段。
- fork(void) 成功后，父进程得到子进程 PID，子进程得到 0，双方从调用返回处继续。失败时原进程得到 -1，无子进程产生。父子私有地址空间逻辑独立，内核可以用写时复制延迟物理页复制。
- shell 在 fork 前解析命令并保存参数。子进程继承这些数据，按需布置 fd，再主动调用 exec。exec 成功替换调用者的程序映像，PID 不变，原来的 shell 在父进程中继续运行。设置了 close-on-exec 的描述符会关闭。PID 1 启动服务也可以用创建进程、准备环境、装载程序的模型来理解。
- 父进程先退出时，活着的子进程可以继续执行。Linux 会重新指定父进程，由合适的祖先 subreaper 或相应的 init 接管。子进程 PID 不变，PPID 可以改变。父进程退出时，已退出但尚未回收的子进程也可以移交给接管者。
- 僵尸进程已停止执行。内核保留退出状态、PID 等少量信息，等待父进程领取。父进程仍活着又长期不回收，记录就可能积累并影响创建新进程。排查时先看 PPID、数量和增长趋势。
- 单个子进程可用 waitpid(pid, &status, 0) 回收，遇 EINTR 重试。长期服务可以在收到 SIGCHLD 后循环调用 waitpid(-1, &status, WNOHANG)，一次处理所有可回收的子进程。通知和实际回收是两步。此处属于示例讲解，尚未完成仓库内的独立实作。
- Linux 上的 Node.js 可以用 process.on('SIGTERM', handler) 来处理停止请求并执行关闭逻辑。SIGKILL 由内核处理，应用代码无法捕获或忽略。

## 课堂习题与取舍

- 理清时间片、抢占、上下文切换和切换开销。批处理关注吞吐，分时关注交互响应，实时关注截止时间。优先级调度题中，四个进程同时到达，按 P2 → P4 → P1 → P3 执行，平均周转时间为 (5 + 8 + 10 + 18) / 4 = 10.25 小时。
- 单核计算/I/O 调度题中，依次执行需 520 ms，同时就绪并按题设优先级调度需 350 ms，差 170 ms。总 CPU 计算量为 330 ms，原策略在 290–310 ms 空闲。另一种安排让 T3 提前进入 I/O，可让整批在 330 ms 完成，但 T1 的完成时刻从 160 ms 推迟到 250 ms。结果来自忽略调度开销的理论时间线。
- 区分饥饿与死锁。统一资源获取顺序可以破坏循环等待，完整授予所需资源可以破坏持有并等待。银行家算法需要各进程的最大需求，授予请求后要保留可行的安全序列。不安全状态不等于已经死锁。
- 资源分配图中，进程指向资源表示申请，资源指向进程表示已分配。同类资源有多个实例时，要同时检查剩余资源和谁能先完成。第一张图可把空闲的 R2 分给 P2，让它先完成并释放资源。第二张图所有请求都在等待其他同样被阻塞的进程，三个进程均陷入死锁。
